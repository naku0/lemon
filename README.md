# LEMON

**LEMON — Lightweight EEG Monitoring Of Neuroactivity** — локальное приложение для получения, предварительной обработки, визуализации и записи ЭЭГ в реальном времени.

Написан на Rust. Поддерживает 1–2 канала, проверку потока, запись исходных отсчётов, фильтрацию, спектр и оценки мощности диапазонов в TUI. Работает без оборудования в режиме `demo`.

> **Приложение не является медицинским изделием.** Оценка качества — инженерная эвристика, не научно валидированная и не клиническая метрика. Классификация намерений, нейросеть, Intent Engine и управление интерфейсами в эту версию не входят.

## Возможности

- Источники: синтетический сигнал (`demo`), воспроизведение записи (`replay`), последовательный порт (`live` с тестовым текстовым форматом).
- 1–2 канала, номинальная частота дискретизации задаётся конфигурацией.
- Потоковая обработка: проверка отсчётов, HP → LP → notch, оценка качества, окно Hann, PSD, мощности диапазонов.
- Запись исходных отсчётов **до** DSP: `raw.csv` + `metadata.json` + `events.csv`.
- TUI с шестью экранами: Sources, Waveform, Spectrum, Bands, Recording, Settings.
- Воспроизведение записанных сеансов с сохранением номеров, значений и временных меток.
- Возможность подключить собственного подписчика обработанных блоков.

## Требования

- Rust stable с Cargo.
- Обычный интерактивный терминал.
- Для первой сборки — доступ к crates.io. Во время работы сеть не используется.
- Linux: системный компилятор/линкер и права чтения/записи выбранного serial-порта. `serialport` собирается без необязательной зависимости `libudev`; возможности перечисления USB-метаданных могут быть ограничены.

Проверено на macOS с Rust 1.93.1.

## Сборка и первый запуск

Из корня проекта:

```sh
cd eeg-receiver
cargo build --locked
cargo test --locked
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo fmt --all --check
cargo run --bin lemon -- demo --config examples/synthetic.json
```

По умолчанию: два канала, 250 Гц, блоки по 25 отсчётов, условные единицы, seed 42, компоненты 6/10/20 Гц, шум, дрейф 0.2 Гц и помеха 50 Гц. Значения настроены для демонстрации. Поля пользователя и электродов оставлены пустыми.

```sh
# Один канал
lemon demo --channels 1

# Два канала, запись сразу при запуске
lemon demo --channels 2 --record

# Короткая демонстрационная запись без TUI
lemon demo --headless --duration 10 --record

# Воспроизводимые аномалии и авторазрыв через 2500 позиций отсчётов
lemon demo --config examples/anomalies.json --record

# Полный пример конфигурации из встроенных значений
lemon config init examples/local.json
```

Запись создаётся в новом каталоге `recordings/<unix-ms>-<session-name>-<suffix>/`. Путь печатается при выходе; во время работы он виден на экране Recording. Пути в конфигурации разрешаются относительно текущего рабочего каталога.

## Установка и CLI

Из каталога `eeg-receiver`:

```sh
cargo install --path crates/eeg-app --locked
lemon --version
lemon
```

Cargo установит бинарный файл `lemon` в `$CARGO_HOME/bin` (обычно `$HOME/.cargo/bin`). После установки он запускается из любого каталога; без подкоманды открывается demo. Системный `PATH` приложение не меняет. Если команда не найдена, запускайте `$HOME/.cargo/bin/lemon` либо добавьте каталог самостоятельно:

```sh
# ~/.zshrc или ~/.bashrc
export PATH="$HOME/.cargo/bin:$PATH"
```

В Windows добавьте `%USERPROFILE%\.cargo\bin` в пользовательский `Path`. Альтернатива установке — `cargo build --release --locked`, затем скопировать `target/release/lemon` (Windows: `lemon.exe`) в каталог из `PATH`.

### Команды

```sh
lemon demo -n 2 -r
lemon live --port /dev/cu.usbmodem123 --baud 115200
lemon live --port /dev/cu.device1 --port /dev/cu.device2
lemon replay recordings/session-name --speed 2
lemon ports
lemon config init                 # стандартный каталог приложения/config.json
lemon config init experiment.json # явно выбранный файл
lemon config check experiment.json
lemon config init --user          # отдельный settings.json
lemon config check --user path/to/settings.json
lemon --help
lemon live --help
```

Файлы при `config init` никогда не перезаписываются.

### Общие опции

Можно ставить до или после подкоманды:

- `-f, --config FILE`
- `-n, --channels 1|2`
- `-r, --record`
- `-t, --duration SECONDS`
- `--headless`
- `-v, --verbose`
- `-h, --help`
- `-V, --version`

Дополнительно: `--data-dir DIR`, `--log-level off|error|warn|info|debug|trace`, `--settings FILE`.

Параметры разных источников не смешиваются: `--port` допустим только у `live`, `--speed` — у `replay`. Два порта требуют двух каналов; при отсутствии `--channels` число каналов выводится из числа портов, если частоту/каналы не задаёт файл эксперимента. Для replay число каналов определяется записью. `--verbose` и `--log-level` взаимоисключающие. Ошибка команды печатает подсказку и возвращает ненулевой код.

Прежний `--seconds` временно оставлен как синоним `--duration`. Общие `--config`, `--channels`, `--record`, `--headless` работают и без подкоманды (demo). Для старых `--source`, `--replay`, `--list-ports`, `--write-config` и `--port` без `live` выводится соответствующая новая команда. Внутренний crate по-прежнему называется `eeg-app`, пользовательский бинарный файл — `lemon`.

## Окружение и пользовательские настройки

```sh
export LEMON_CONFIG="$HOME/.config/lemon/config.json"
export LEMON_DATA_DIR="$HOME/EEG-recordings"
export LEMON_LOG="info"
lemon demo
```

Указанный путь `LEMON_CONFIG` должен существовать на вашей системе.

### Стандартные каталоги

| ОС | Каталог |
|---|---|
| macOS | `~/Library/Application Support/LEMON/` |
| Linux | `$XDG_CONFIG_HOME/lemon/`, обычно `~/.config/lemon/` |
| Windows | `%APPDATA%\LEMON\` |

`config.json` — воспроизводимая конфигурация эксперимента; `settings.json` — личные предпочтения отображения. При отсутствии явного `--config`/`LEMON_CONFIG` автоматически загружается `config.json` рядом с выбранным `settings.json`, если существует. Чтение не создаёт файл настроек; `S` в Settings или `config init --user` создаёт его явно. `--settings FILE` удобно для переносимой установки и изоляции тестов.

### Приоритет значений

**CLI → env → пользовательские настройки → файл эксперимента → встроенные значения.**

Примеры:

- Каталог: `--data-dir` → `LEMON_DATA_DIR` → `settings.storage.directory` → `config.recording_dir` → `recordings`.
- Путь эксперимента: `--config` → `LEMON_CONFIG` → стандартный `config.json`.
- Уровень журнала: `--verbose` / `--log-level` → `LEMON_LOG` → `warn`.

Пустые пути и неизвестные уровни дают ошибку; значения env проверяются даже при наличии переопределения. `~` внутри JSON не раскрывается shell: используйте абсолютный путь.

В headless журнал идёт в stderr, в TUI — в `lemon.log` рядом с `settings.json`, чтобы не портить экран. `-v` включает подробности запуска и периодические счётчики. Журнал диагностический, может объединять частые события; полный журнал записываемого эксперимента остаётся в `events.csv`.

Настройки интерфейса не передаются в DSP и не включаются в metadata эксперимента. Исторические поля `tui_hz` и `recording_dir` сохранены для совместимости; UI использует `tui_hz` лишь как fallback при отсутствии пользовательского файла. Смена темы/FPS не меняет эти поля в сохранённом эксперименте. Имя сеанса, пользователь, электроды и заметка относятся к эксперименту и записываются в metadata.

## Архитектура

```text
crates/
  eeg-core/        блоки, отсчёты, конфигурация, события, bounded broadcast, кольцевой буфер
  eeg-source/      SignalSource, synthetic, replay, serial transport + тестовый парсер
  eeg-processing/ валидация отсчётов, фильтры, Hann FFT/PSD, мощности, качество
  eeg-storage/    metadata.json + raw.csv + events.csv, потоковое чтение записи
  eeg-tui/        шесть экранов, настройки, темы, клавиатура и история готовых результатов
  eeg-app/        CLI, потоки, команды, жизненный цикл, тестовый потребитель
examples/         synthetic.json, anomalies.json
scripts/smoke.py  сквозная проверка в Unix-псевдотерминале
```

```text
SignalSource (поток приёма)
        │ bounded очередь: 128 сообщений
        ▼
  запись RAW ───────────► raw.csv + metadata.json
        │
  Processor: проверка → HP → LP → notch → качество → окно → PSD → мощности
        │                                      │
        ├──────────────────────────────────────► events.csv
        ▼
  Broadcast<ProcessedSignalBlock>
        ├── TUI (отдельный поток приложения, очередь 64)
        ├── тестовый потребитель (отдельный поток, очередь 64)
        └── подключаемые внутренние потребители
```

Запись идёт **до DSP**, исходные значения не перезаписываются. Ошибки и артефакты сохраняются событиями с номером блока. Чтение источника и запись не зависят от частоты кадров, переключения экранов или паузы визуализации.

Медленный необязательный подписчик пропускает новые блоки с явным счётчиком `dropped`; исходная запись через эту очередь не проходит. Переполнение очереди приёма останавливает источник с `SourceError`, а не скрывает потерю. Медленный диск может вызвать такое переполнение: безграничного буфера нет. Команды начала/остановки применяются на границе обрабатываемых блоков. Запись буферизуется и синхронизируется с диском раз в секунду, при остановке записи и при выходе.

## TUI

Рекомендуемый размер терминала — от 120 × 35. Окно можно изменять во время работы.

### Клавиши

| Клавиша | Действие |
|---|---|
| `1`–`6`, `Tab`, `Shift+Tab` | Sources, Waveform, Spectrum, Bands, Recording, Settings |
| `r` | Начать новый сеанс / остановить и сбросить запись |
| `m` | Ввести текстовую метку; `Enter` сохранить, `Esc` отменить |
| `Space` | Пауза/продолжить только обновление графиков и оценок |
| `v` | Waveform: raw → filtered → оба (по умолчанию оба) |
| `c` | Оба канала → канал 1 → канал 2 |
| `+`, `-` | Масштаб Waveform от 1 до 10 секунд |
| `a` | Waveform: автоматический / фиксированный амплитудный масштаб |
| `p` | Bands: абсолютная / относительная мощность / изменение от baseline |
| `?` | Справка поверх текущего экрана; `Esc` закрывает только справку |
| `d` | Отключить источник, обработать очередь и завершить запись |
| `q`, `Esc`, `Ctrl+C` | Выход с обязательным подтверждением при активной записи |

Верхняя панель показывает `LEMON`, DEMO/LIVE/REPLAY, каналы, Hz, соединение, REC с таймером и заметный `PAUSED — DISPLAY ONLY`. Зелёный — Good, жёлтый — Acceptable, красный — Poor/ошибка/REC, серый — нет данных. Состояния подписаны текстом и понятны без цвета. Подписи основных экранов — английские; предупреждение о выходе при записи — на русском. Компактный режим включается автоматически для терминалов меньше 110 × 30 или вручную. Ниже 52 × 14 показывается просьба увеличить окно; обработка и запись продолжаются.

### Экран Settings

Группы General, Storage, Appearance, Waveform, Spectrum and Bands, Advanced.

- `↑/↓` — выбрать поле.
- `Enter` — открыть редактор или переключить значение.
- `←/→` — менять значение.
- `Space` — переключить checkbox.
- `S` — сохранить.
- `R` — восстановить текущую группу.
- `Ctrl+R` — полный сброс с подтверждением.
- `Esc` — отменить редактирование.

На этой вкладке `R` относится к сбросу группы; для записи переключитесь на другой экран.

- **General**: FPS, стартовая вкладка, подтверждение выхода, Unicode/ASCII, компактный режим.
- **Storage**: каталог, имя сеанса, создание каталога, итог записи.
- **Appearance**: Dark, Light, HighContrast, Monochrome, Custom; отдельные цвета Raw/Filtered, каналов и диапазонов, легенды и рамки. Изменение цвета включает Custom; тема применяется сразу ко всем экранам. В Monochrome остаются текстовые подписи качества. Режим ASCII заменяет графические символы рамок и маркеры; введённый пользователем текст не транслитерируется.
- **Waveform**: Raw/Filtered/Both, окно, автомасштаб/фиксированный масштаб, каналы.
- **Spectrum and Bands**: логарифмическая PSD, вид мощности, видимые диапазоны (имена через запятую; пусто — все), отображение готовой EMA, длительность истории. EMA применяется только к абсолютной мощности: используется уже вычисленное `smoothed` из DSP.
- **Advanced**: HP/LP, notch, частота notch, FFT window/hop и границы диапазонов только для чтения; изменение требует редактирования JSON эксперимента и перезапуска.

Внизу Settings указано, когда применяется поле: оформление — сразу; стартовая вкладка — при следующем запуске; каталог и имя — для следующей записи. Каталог, заданный CLI/env, сохраняет приоритет над дефолтом Settings на текущем запуске. Для разового назначения конкретной записи можно отредактировать Destination на экране Recording. Сохранение Settings не изменяет текущий эксперимент или активную запись.

### Экраны данных

**Sources** показывает порты, выбранный источник, номинальную и измеренную частоту поступления, суммарные канало-отсчёты, пропуски, ошибки, выбросы и рассогласование.

**Waveform** использует точки, чтобы не рисовать выдуманные линии через пропуски. Серый — raw, голубой — filtered. Автомасштаб учитывает исходные выбросы.

**Spectrum** сравнивает Raw/Filtered PSD цветами темы и с легендой, выделяет диапазоны, показывает частоту максимального ненулевого filtered-пика и долю raw-мощности в 48–52 Гц. Ось X — Hz, Y — единицы²/Hz или dB относительно 1 единицы²/Hz. Для log-шкалы нижний предел — −120 dB; данные обработки не меняются.

**Bands** показывает историю Theta, Alpha/Mu и Beta для выбранных каналов и компактную таблицу текущих мощностей/асимметрии. `P` переключает абсолютную мощность, процент общей мощности и процент изменения от baseline. По умолчанию история — 60 секунд, настраивается 1–3600 секунд; общий предел — 10000 точек для всех каналов и диапазонов. `None` не рисуется как ноль; пропуски, потеря блоков подписчиком и пауза разбивают историю на отдельные линии.

**Recording** позволяет до начала записи редактировать имя, пользователя, электроды, заметку и Destination (`↑/↓`, `Enter`). Во время записи поля заблокированы. Создание каталога проверяется при старте; отказ показывается сообщением, источник продолжает работать. После метки выводится подтверждение сохранения. После остановки показываются длительность, число отсчётов, пропуски, ошибки и путь (можно отключить в Storage). При выходе с активной записью требуется `Y`; `N` возвращает в приложение. Заданная CLI `--duration` и headless SIGINT завершают запись автоматически со сбросом очереди.

После EOF или отключения источник закрывается и запись сбрасывается; TUI остаётся открытым для просмотра результата до `q`. Для нового подключения нужно перезапустить приложение. В headless-режиме EOF завершает процесс автоматически.

## Конфигурация

JSON с проверкой неизвестных полей и значений. Отсутствующие поля получают значения по умолчанию. Для эксперимента лучше сохранять полный файл.

| Раздел / параметр | Смысл |
|---|---|
| `source.mode` | `synthetic`, `replay`, `serial-test` |
| `source.channels`, `sample_rate_hz`, `block_size` | 1 или 2 канала; номинальная частота; размер синтетического блока 1–4096 |
| `source.components` | Список `{hz, amplitude}` синусоидальных составляющих |
| `source.noise`, `mains`, `drift`, `seed` | Амплитуды равномерного шума, помехи 50 Гц, дрейфа 0.2 Гц; воспроизводимый seed |
| `source.anomalies.skip_every` | Пропуск каждой N-й позиции (0 выключает; N ≥ 2) |
| `spike_every`, `spike_amplitude` | Период и амплитуда одиночных выбросов |
| `channel2_delay_ms` | Сдвиг времени/сигнала второго синтетического канала |
| `disconnect_after_samples` | Окончание после N позиций; `null` — бесконечно |
| `source.ports`, `baud_rate`, `serial_idle_timeout_ms` | Порты, скорость, таймаут без корректного пакета (по умолчанию 3000 мс) |
| `source.units` | Единицы serial-источника либо `null`; синтетика всегда в условных единицах |
| `source.replay_path`, `replay_speed` | Каталог записи и скорость 0.01–100 |
| `processing.high_pass_hz`, `low_pass_hz` | Потоковые HP и LP второго порядка |
| `notch`, `notch_hz`, `notch_q` | Включение и параметры notch; по умолчанию 50 Гц, Q = 30 |
| `window_samples`, `hop_samples` | Окно Hann и шаг: 500/50 при 250 Гц дают 2 с и обновление каждые 0.2 с |
| `bands` | `{name, low_hz, high_hz}`; левая граница включена, правая исключена |
| `smoothing` | EMA абсолютной мощности: `α × current + (1−α) × previous` |
| `baseline` | Массив `[канал][диапазон]` положительных абсолютных мощностей; пустой массив отключает baseline |
| `expected_abs_max`, `outlier_step`, `flat_stddev` | Порог насыщения, скачка между соседними отсчётами, малой изменчивости |
| `mains_ratio_limit`, `sync_tolerance_ms` | Порог raw-мощности 48–52 Гц; допустимое рассогласование подтверждённых часов |
| `tui_hz` | Частота перерисовки 1–60; по умолчанию 15 |
| `recording_dir`, `session` | Каталог, имя сеанса, `user_id`, `electrodes`, `notes` |

Частоты проверяются относительно Найквиста. Параметры качества относятся к условной синтетической шкале; для реальных данных их надо обосновать заново.

Каждый канал имеет отдельное состояние фильтра. Пропуск сбрасывает его непрерывное спектральное окно и фильтры; значения не интерполируются. Неконечные и численно опасные значения остаются в RAW, но дают `None` в filtered и флаг `InvalidPacket`. Выбросы и насыщение маркируются; конечные значения в обычном числовом диапазоне не заменяются. После сброса фильтра возможен переходный процесс — спектральное накопление начинается заново.

PSD — односторонний периодограммный спектр с окном Hann и нормировкой на частоту дискретизации и энергию окна; постоянная составляющая окна вычитается. Интеграл PSD даёт мощность в единицах². Относительная мощность — мощность диапазона, делённая на общую filtered-мощность ненулевых частот, **не** на сумму пересекающихся диапазонов. EMA обновляется при публикации нового спектра. При больших блоках внутри блока могут рассчитываться несколько окон, потребителю передаётся последнее.

Theta 4–8, Alpha/Mu 8–13, Beta 13–30 Гц — **оценки мощности частотных компонентов**, не отдельные сигналы. Alpha и Mu различаются расположением электродов и экспериментальным контекстом. Мощность 8–13 Гц сама по себе не является MuERD. Можно задать отдельные Alpha и Mu с одинаковыми границами: их численные мощности будут одинаковыми.

Изменение от baseline: `100 × (power / baseline − 1)`. Асимметрия: `(P1 − P2) / (P1 + P2)`, одинаковое значение в строках обоих каналов. Она доступна только при подтверждённой общей шкале времени и достаточной синхронизации.

## Формат сеанса

Версия 1.

```text
session-directory/
  metadata.json
  raw.csv
  events.csv
```

**`metadata.json`**: версия формата/приложения, Unix-время начала записи в миллисекундах, устройства, каналы, временная шкала, единицы, синтетический seed и **вся эффективная конфигурация**, включая пользователя, электроды, источник, фильтры, спектр, диапазоны, baseline, аномалии и заметки. Идентификаторы устройств уточняются по первому блоку атомарной заменой metadata-файла.

**`raw.csv`**: `block_sequence`, `block_started_ns`, `sample_rate_hz`, `source`, `synchronized_clock`, `block_flags`, общие `sequence`/`timestamp_ns` и для каждого канала `chN_id`, `chN_device`, `chN_sequence`, `chN_timestamp_ns`, `chN_value`, `chN_flags`. Общие номер/время берутся из первого присутствующего канала; для анализа используйте индивидуальные поля. У несинхронных устройств отсутствующий канал имеет пустые ячейки, **не нули**. Флаги кодируются JSON-массивами внутри CSV-полей. Исходные f64 сохраняются с точностью обратного чтения. Отсутствующие отсчёты не создают искусственных строк.

**`events.csv`**: `timestamp_ns`, `kind`, `text`; метки, подключения/отключения, ошибки, пропуски, артефакты. События DSP содержат `block=<номер>` для связи с raw. CSV корректно экранирует запятые, кавычки и переносы строк. Пакет, который невозможно разобрать, фиксируется диагностическим событием, а не выдуманным числом.

Временные метки — наносекунды относительно начала **источника**, а не начала каждой записи; несколько записей одного запуска продолжают эту шкалу. Wall-clock начала записи хранится отдельно в metadata. Для synthetic номера и время определяет модель.

## Воспроизведение

```sh
lemon replay recordings/ИМЯ-КАТАЛОГА
lemon replay recordings/ИМЯ-КАТАЛОГА --headless --speed 2
```

Чтение потоковое: вся запись в память не загружается. Сохраняются номера, исходные значения и временные метки, включая относительные сдвиги каналов. Блок выдаётся по времени последнего отсчёта в нём; скорость меняет только темп выдачи. Метки и системные события также воспроизводятся с префиксом `Replay/`. Префикс не превращает историческое событие отключения в ошибку текущего устройства.

Число каналов и частота всегда берутся из metadata. Без `--config` обработка и описание сеанса тоже восстанавливаются из metadata. С `--config` используются заданные пользователем настройки обработки: можно сравнить иной notch/полосу с тем же RAW. Фильтры стартуют с нулевого состояния; если запись началась посреди работы источника, начальные filtered-значения могут отличаться от первоначального live-сеанса.

## Последовательный порт

```sh
lemon ports
lemon live --port /dev/cu.usbmodemXXXX --baud 115200 --channels 1
# Один порт: два значения в строке
lemon live --port /dev/cu.usbmodemXXXX --channels 2
# Два независимых порта: по одному значению в строке
lemon live --port /dev/cu.deviceA --port /dev/cu.deviceB --channels 2
```

В Windows вместо пути указывается, например, `COM3`. Необходимую номинальную частоту и фильтры задайте через `--config`. Используются 8N1 и отсутствие flow control (значения serialport по умолчанию).

Тестовый формат — ASCII/UTF-8, `LF` или `CRLF`, `123.5` для одного канала либо `123.5,-42` для двух. Не более 256 байт на строку, только конечные числа; строки неверной длины/формата дают событие, следующая корректная строка снова принимается. Чтение порта отделено от `parse_test_line`. Порты закрываются при выходе и по `d`. Ошибка открытия диагностируется до входа в TUI, ошибка чтения отображается в TUI и events.

Для двух портов приходящие отсчёты идут в раздельных каналах с индивидуальными метками. Удалённые отсчёты, которые вообще не появились в текстовом потоке, нельзя достоверно обнаружить без аппаратных sequence numbers; локальные номера строк выявляют только отброшенные некорректные строки. Частота в конфигурации — предположение оператора, не измеренная характеристика устройства. Спектральные оценки предполагают равномерную аппаратную дискретизацию; метки прихода содержат USB/OS jitter. Часы двух устройств не синхронизируются автоматически, ресемплинга нет.

## Свой потребитель данных

Не требуется менять TUI или Processor. Подписку добавляют при сборке приложения:

```rust
use eeg_core::{Broadcast, Config, ProcessedSignalBlock};
use eeg_app::Runtime;

let config = Config::default();
let source = eeg_source::open(&config.source)?;
let mut bus = Broadcast::<ProcessedSignalBlock>::default();
let features = bus.subscribe(64);
let runtime = Runtime::start_with_bus(config, source, false, bus)?;
// Собственный поток: features.receiver.recv() -> Arc<ProcessedSignalBlock>.
// Проверяйте features.dropped; это ограниченный, а не гарантированно lossless канал.
// После работы: runtime.shutdown()?; дождаться завершения своего потребителя.
```

Встроенный тестовый потребитель получает блоки независимо от TUI; счётчики видны в Sources и итоговом выводе. Для будущей записи производных данных можно подключить такой же потребитель. Для lossless-потребителя потребуется явно выбрать политику backpressure; raw уже записывается напрямую.

## Проверки и ограничения

```sh
cargo fmt --all --check
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo build --locked
python3 scripts/smoke.py
```

Rust-тесты проверяют парсер, каналы, пропуски, сохранение состояния фильтров, PSD известной синусоиды, относительную мощность/baseline, notch, короткое окно, Найквист, seed, кольцевые буферы, round-trip записи, маркеры replay, повреждённый CSV, независимость записи от TUI, стороннего подписчика и завершение после отключения. На Unix тесты `TTYPort::pair()` проверяют serial transport, восстановление после ошибочных/слишком длинных строк, два порта и отключение.

`smoke.py` запускает настоящий TUI в PTY, переключает экраны, включает запись, вводит метку, ставит визуализацию на паузу, выходит через `q` и `Ctrl+C`, проверяет восстановление termios/курсора/alternate screen и воспроизводит запись с точным совпадением количества отсчётов. Проверяется также внешний SIGINT в headless. На macOS открытие обычного PTY как serial с аппаратной baud-настройкой не поддерживается драйвером: эта часть CLI smoke пропускается; транспорт проверяется Rust-тестами пары PTY. На Linux smoke дополнительно проверяет serial CLI.

### Ограничения

- Один источник на запуск; до двух каналов.
- Нет автоматического reconnect, восстановления повреждённого CSV и гарантированного real-time планировщика.
- Один Hann-периодограммный спектр вместо усреднения Welch.
- Baseline задаётся конфигурацией.
- Очищенные отсчёты не записываются отдельным файлом.
- Пороговые эвристики не заменяют анализ артефактов ЭЭГ.
- История Waveform ограничена 10 секундами и 100000 точками на канал, история Bands — 10000 точками, список событий — 30 строками, очереди — фиксированной ёмкостью.
- Размер FFT ограничен 65536, блока — 4096, CSV-записи — 64 КиБ, metadata/config/settings — 1 МиБ.
- Нет облака, БД, сетевого API и фонового бесконечного накопления данных.
- RAII и panic hook восстанавливают терминал при штатном выходе и Rust panic; SIGKILL, отключение питания и аппаратный сбой ОС программно обработать невозможно. При принудительном уничтожении процесса часть последней секунды буферизованной записи может не сохраниться.
