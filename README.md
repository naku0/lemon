# LEMON

**LEMON — Lightweight EEG Monitoring Of Neuroactivity**

Локальное приложение для получения, предварительной обработки, визуализации и записи ЭЭГ в реальном времени. Написано на Rust. Поддерживает 1–2 канала, проверку потока, запись исходных отсчётов, фильтрацию, спектр и оценки мощности диапазонов в TUI. Работает без оборудования в режиме `demo`.

Дополнительно: импорт внешних записей (CSV, BiTronics DAT, прямой DMOV подтверждённого профиля Лаб2 и старый DMOV через связанные DAT), потоковый технический анализ (`lemon analyze`) и воспроизводимые Jupyter-отчёты (`lemon report`) — локальные, portable ZIP и Colab.

> **Приложение не является медицинским изделием.**
> Оценка качества — инженерная эвристика, не научно валидированная и не клиническая метрика. Классификация намерений, нейросеть, Intent Engine и управление интерфейсами в эту версию не входят. `summary.md` описывает только численные характеристики и выполненную обработку; интерпретация нейрофизиологического, когнитивного или медицинского значения остаётся профильному специалисту.

## 1. Возможности

- **Источники:** синтетический сигнал (`demo`), воспроизведение записи (`replay`), последовательный порт (`live`: CSV или бинарный tagged-u8).
- **Каналы:** 1–2, номинальная частота дискретизации задаётся конфигурацией.
- **Потоковая обработка:** проверка отсчётов, HP → LP → notch, оценка качества, окно Hann, PSD, мощности диапазонов.
- **Запись исходных отсчётов до DSP:** `raw.csv` + `metadata.json` + `events.csv`.
- **TUI с шестью экранами:** Sources, Waveform, Spectrum, Bands, Recording, Settings.
- **Воспроизведение** записанных сеансов с сохранением номеров, значений и временных меток.
- **Импорт** CSV, BiTronics DAT и прямой двухканальный DMOV подтверждённого профиля Лаб2.
- **Потоковый `lemon analyze`** с AnalysisBundle, полным набором FFT-окон и нейтральным техническим резюме.
- **Воспроизводимые Jupyter-отчёты:** локальный выполненный notebook, переносимый ZIP и самодостаточный Colab notebook.
- **Расширяемость:** возможность подключить собственного подписчика обработанных блоков.

## 2. Требования

| Компонент | Требование |
|---|---|
| Rust | stable с Cargo |
| Терминал | интерактивный |
| Сеть | только для первой сборки (crates.io) и `lemon report setup` |
| Python (для отчётов) | >= 3.10 |
| Linux | системный компилятор/линкер, права на serial-порт |

`serialport` собирается без необязательной зависимости `libudev`; возможности перечисления USB-метаданных могут быть ограничены.

Для `lemon report setup` нужен доступ к Python Package Index или настроенному пользователем зеркалу. Обычная запись, replay, анализ и генерация `--no-execute`/`--colab` не выполняют сетевые запросы. Colab содержит выключенную по умолчанию opt-in ячейку установки отсутствующих пакетов.

Проверено на macOS с Rust 1.93.1.

## 3. Сборка и первый запуск

Из корня проекта:

```sh
cd lemon
cargo build --locked
cargo test --locked
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo fmt --all --check
cargo run --bin lemon -- demo --config examples/synthetic.json
```

**Параметры по умолчанию:** два канала, 250 Гц, блоки по 25 отсчётов, условные единицы, seed 42, компоненты 6/10/20 Гц, шум, дрейф 0.2 Гц, помеха 50 Гц. Значения настроены для демонстрации. Поля пользователя и электродов оставлены пустыми.

```sh
# Один канал
lemon demo --channels 1

# Два канала, запись сразу при запуске
lemon demo --channels 2 --record

# Короткая демонстрационная запись без TUI
lemon demo --headless --duration 10 --record

# Воспроизводимые аномалии и авторазрыв через 2500 позиций
lemon demo --config examples/anomalies.json --record

# Полный пример конфигурации из встроенных значений
lemon config init examples/local.json
```

Запись создаётся в каталоге `recordings/<unix-ms>-<session-name>-<suffix>/`. Путь печатается при выходе и виден на экране Recording. Пути в конфигурации разрешаются относительно текущего рабочего каталога.

## 4. Установка и CLI

### 4.1. Установка

```sh
cd lemon
cargo install --path crates/app --locked
lemon --version
lemon
```

Cargo установит бинарный файл `lemon` в `$CARGO_HOME/bin` (обычно `$HOME/.cargo/bin`). Без подкоманды открывается demo.

**Unix (bash/zsh):**

```sh
export PATH="$HOME/.cargo/bin:$PATH"
```

**Windows:** добавьте `%USERPROFILE%\.cargo\bin` в пользовательский `Path`.

**Альтернатива:** `cargo build --release --locked`, затем скопируйте `target/release/lemon` (Windows: `lemon.exe`) в каталог из `PATH`.

### 4.2. Команды

```sh
lemon demo -n 2 -r
lemon live --port /dev/cu.usbmodem123 --baud 115200
lemon live --port /dev/cu.device1 --port /dev/cu.device2
lemon replay recordings/session-name --speed 2
lemon ports

# Конфигурация
lemon config init                 # стандартный каталог
lemon config init experiment.json # явный файл
lemon config check experiment.json
lemon config init --user          # отдельный settings.json
lemon config check --user path/to/settings.json

# Анализ и отчёты
lemon analyze recording.csv
lemon report setup
lemon report doctor
lemon report recording.csv
lemon report recording.csv --portable
lemon report recording.csv --colab
```

Файлы при `config init` **никогда не перезаписываются**.

### 4.3. Общие опции

Можно ставить до или после подкоманды:

| Опция | Описание |
|---|---|
| `-f, --config FILE` | Путь к файлу конфигурации |
| `-n, --channels 1\|2` | Число каналов |
| `-r, --record` | Начать запись |
| `-t, --duration SECONDS` | Длительность |
| `--headless` | Без TUI |
| `-v, --verbose` | Подробный вывод |
| `-h, --help` | Справка |
| `-V, --version` | Версия |

Дополнительно: `--data-dir DIR`, `--log-level off|error|warn|info|debug|trace`, `--settings FILE`.

### 4.4. Правила совместимости

- `--port` — только у `live`, `--speed` — только у `replay`.
- Два порта требуют двух каналов; без `--channels` число каналов выводится из числа портов.
- Для replay число каналов определяется записью.
- `--verbose` и `--log-level` взаимоисключающие.
- Прежний `--seconds` — синоним `--duration`.
- Общие `--config`, `--channels`, `--record`, `--headless` работают и без подкоманды (demo).
- Для устаревших `--source`, `--replay`, `--list-ports`, `--write-config` и `--port` без `live` выводится подсказка о новой команде.

Внутренний crate приложения называется `app`, пользовательский бинарный файл — `lemon`.

## 5. Окружение и пользовательские настройки

### 5.1. Переменные окружения

```sh
export LEMON_CONFIG="$HOME/.config/lemon/config.json"
export LEMON_DATA_DIR="$HOME/EEG-recordings"
export LEMON_LOG="info"
lemon demo
```

Указанный путь `LEMON_CONFIG` должен существовать на вашей системе.

### 5.2. Стандартные каталоги

| ОС | Каталог |
|---|---|
| macOS | `~/Library/Application Support/LEMON/` |
| Linux | `$XDG_CONFIG_HOME/lemon/`, обычно `~/.config/lemon/` |
| Windows | `%APPDATA%\LEMON\` |

### 5.3. Файлы настроек

- **`config.json`** — воспроизводимая конфигурация эксперимента.
- **`settings.json`** — личные предпочтения отображения.

При отсутствии явного `--config`/`LEMON_CONFIG` автоматически загружается `config.json` рядом с выбранным `settings.json`, если существует. Чтение не создаёт файл настроек; `S` в Settings или `config init --user` создаёт его явно. `--settings FILE` удобно для переносимой установки и изоляции тестов.

### 5.4. Приоритет значений

**CLI → env → пользовательские настройки → файл эксперимента → встроенные значения.**

Примеры:

- Каталог: `--data-dir` → `LEMON_DATA_DIR` → `settings.storage.directory` → `config.recording_dir` → `recordings`.
- Путь эксперимента: `--config` → `LEMON_CONFIG` → стандартный `config.json`.
- Уровень журнала: `--verbose` / `--log-level` → `LEMON_LOG` → `warn`.

Пустые пути и неизвестные уровни дают ошибку; значения env проверяются даже при наличии переопределения. `~` внутри JSON не раскрывается shell: используйте абсолютный путь.

### 5.5. Журналирование

- **Headless:** журнал идёт в stderr.
- **TUI:** журнал идёт в `lemon.log` рядом с `settings.json`, чтобы не портить экран.

`-v` включает подробности запуска и периодические счётчики. Журнал диагностический, может объединять частые события; полный журнал записываемого эксперимента остаётся в `events.csv`.

Настройки интерфейса не передаются в DSP и не включаются в metadata эксперимента. Исторические поля `tui_hz` и `recording_dir` сохранены для совместимости. Имя сеанса, пользователь, электроды и заметка относятся к эксперименту и записываются в metadata.

## 6. Архитектура

### 6.1. Структура проекта

```text
crates/
  core/            блоки, отсчёты, конфигурация, события, bounded broadcast, кольцевой буфер
  source/          SignalSource, synthetic, replay, Serial transport + CSV/tagged-u8 decoders, probe
  processing/      валидация отсчётов, фильтры, Hann FFT/PSD, мощности, качество
  storage/         metadata.json + raw.csv + events.csv, потоковое чтение записи
  tui/             шесть экранов, настройки, темы, клавиатура и история
  app/             CLI, потоки, команды, жизненный цикл, тестовый потребитель
  analysis/        потоковый AnalysisBundle и технические численные итоги
  report/          nbformat 4 renderer, управляемый Python, portable ZIP и Colab Dataset
examples/          synthetic.json, anomalies.json
scripts/smoke.py               сквозная проверка в Unix-псевдотерминале
scripts/report_smoke.py        analyze → local/portable/Colab без реальных данных
```

### 6.2. Поток данных

```text
SignalSource (поток приёма)
        │ bounded очередь: 128 сообщений
        ▼
  запись RAW ───────────► raw.csv + metadata.json
        │
  Processor: проверка → HP → LP → notch → качество → окно → PSD → мощности
        │                                      │
        ├──────────────────────────────────────► events.csv
        ▼
  Broadcast<ProcessedSignalBlock>
        ├── TUI (отдельный поток приложения, очередь 64)
        ├── тестовый потребитель (отдельный поток, очередь 64)
        └── подключаемые внутренние потребители
```

### 6.3. Ключевые принципы

- Запись идёт **до DSP**, исходные значения не перезаписываются.
- Ошибки и артефакты сохраняются событиями с номером блока.
- Чтение источника и запись не зависят от частоты кадров, переключения экранов или паузы визуализации.
- Медленный необязательный подписчик пропускает новые блоки с явным счётчиком `dropped`.
- Переполнение очереди приёма останавливает источник с `SourceError`, а не скрывает потерю.
- Запись буферизуется и синхронизируется с диском раз в секунду, при остановке записи и при выходе.

## 7. TUI

### 7.1. Рекомендации

Рекомендуемый размер терминала — от **120 × 35**. Окно можно изменять во время работы. Компактный режим включается автоматически для терминалов меньше 110 × 30. Ниже 52 × 14 показывается просьба увеличить окно; обработка и запись продолжаются.

### 7.2. Горячие клавиши

| Клавиша | Действие |
|---|---|
| `1`–`6`, `Tab`, `Shift+Tab` | Sources, Waveform, Spectrum, Bands, Recording, Settings |
| `r` | Начать новый сеанс / остановить и сбросить запись |
| `m` | Ввести текстовую метку; `Enter` сохранить, `Esc` отменить |
| `Space` | Пауза/продолжить только обновление графиков и оценок |
| `v` | Waveform: raw → filtered → оба (по умолчанию оба) |
| `g` / `G` | Waveform: Line → Points → Envelope |
| `c` | Оба канала → канал 1 → канал 2 |
| `+`, `-` | Масштаб Waveform от 1 до 10 секунд |
| `a` | Waveform: автоматический / фиксированный амплитудный масштаб |
| `p` | Bands: абсолютная / относительная мощность / изменение от baseline |
| `?` | Справка поверх текущего экрана; `Esc` закрывает только справку |
| `d` | Отключить источник, обработать очередь и завершить запись |
| `q`, `Esc`, `Ctrl+C` | Выход с обязательным подтверждением при активной записи |

### 7.3. Верхняя панель

Показывает `LEMON`, DEMO/LIVE/REPLAY, каналы, Hz, соединение, REC с таймером и `PAUSED — DISPLAY ONLY`.

| Цвет | Значение |
|---|---|
| Зелёный | Good |
| Жёлтый | Acceptable |
| Красный | Poor / ошибка / REC |
| Серый | Нет данных |

Состояния подписаны текстом и понятны без цвета. Подписи основных экранов — английские; предупреждение о выходе при записи — на русском.

### 7.4. Экран Settings

Категории: **Appearance, Recording, Acquisition, Processing, Advanced**. На широком экране список слева, на компактном — сверху с названием и номером категории; справа/ниже только её параметры. Длинные значения дополнительно показаны в нижней панели. Формат `settings.json` совместим с прежними версиями.

**Управление:**

- `[` / `]` или `PageUp` / `PageDown` — выбрать категорию.
- `↑/↓` — выбрать поле внутри категории.
- `Enter` — открыть редактор или переключить значение.
- `←/→` — менять значение.
- `Space` — переключить checkbox.
- `S` — сохранить.
- `R` — восстановить текущую группу.
- `Ctrl+R` — полный сброс с подтверждением.
- `Esc` — отменить редактирование.

| Группа | Параметры |
|---|---|
| Appearance / Interface | FPS, стартовая вкладка, подтверждение выхода, Unicode/ASCII, компактный режим |
| Appearance / Colors | Dark, Light, HighContrast, Monochrome, Custom; цвета Raw/Filtered, каналов и диапазонов, легенды, рамки |
| Appearance / Charts | Raw/Filtered/Both, Line/Points/Envelope, окно, масштаб, видимые каналы, яркость, порог Envelope, допуск разрыва; PSD, мощность, EMA, история |
| Recording | Каталог, имя сеанса, создание каталога, итог записи, метаданные сеанса |
| Acquisition | Источник, частота, входные каналы, единицы, Serial/replay (только чтение) |
| Processing | HP/LP, notch, FFT window/hop, диапазоны, пороги качества (только чтение; JSON/CLI и новый запуск) |
| Advanced | Версия, размер блока, сброс предпочтений с подтверждением |

Внизу Settings указано, когда применяется поле: оформление — сразу; стартовая вкладка — при следующем запуске; каталог и имя — для следующей записи. Сохранение Settings не изменяет текущий эксперимент или активную запись.

Dark использует самостоятельную RGB-палитру: тёмный сине-серый фон, светлый текст, голубой Raw, бирюзовый Filtered, синий/оранжевый для каналов, фиолетовый Theta, зелёный Alpha/Mu, янтарный Beta. Фокус и предупреждения — жёлтые, ошибки/REC — коралловые. Light сохраняет отдельные цвета на белом фоне; HighContrast/Monochrome доступны для ограниченных терминалов. Подписи каналов и легенды сохраняются независимо от цвета. Custom также принимает `#RRGGBB`, прежние имена цветов работают. `R` сбрасывает прежнюю группу предпочтений выбранного поля, `Ctrl+R` — все пользовательские настройки с подтверждением; DSP не меняется.

### 7.5. Экраны данных

**Sources** — порты, выбранный источник, номинальная и измеренная частота поступления, суммарные канало-отсчёты, пропуски, ошибки, выбросы, рассогласование.

**Waveform** — по умолчанию **Line**. `G` переключает Line → Points → Envelope; выбор сохраняется через `S` в Settings.

- **Line** рисует каждый непрерывный сегмент отдельной линией. Разрыв создаётся при нарушении sequence, времени, идентификатора устройства/канала, `LostSample`/`InvalidPacket`/`Disconnected`, отсутствующем filtered-значении и возобновлении после паузы.
- **Points** показывает отдельные отсчёты заметным Dot-маркером.
- **Envelope** делит видимое окно на колонки терминала, сохраняя **min/max** (включая одиночные пики), отдельно для Raw и Filtered. Вертикальные отрезки не соединяются между колонками; при разрыве внутри колонки рисуются две отдельные точки.

На каждый сигнал выводится не более двух точек на колонку; агрегация только для отображения, исходные значения и DSP не меняются. По умолчанию в совместном виде Raw приглушён (`raw_brightness=0.65`), Filtered ярче (`filtered_brightness=1`). Line/Envelope используют Braille в Unicode и Dot в ASCII; Points всегда Dot.

Поля `settings.json` → `waveform`:

| Поле | Значение |
|---|---|
| `style` | `Line`, `Points`, `Envelope` |
| `raw_brightness`, `filtered_brightness` | 0.1–1 |
| `auto_envelope_threshold` | 0–1000 отсчётов/колонку, 0 выключает |
| `gap_tolerance` | 1–100 номинальных периодов, по умолчанию 2.5 |

Явный выбор через `G` или Settings отключает автоматику. Старые настройки загружаются с новыми значениями по умолчанию. Окно — 1–10 секунд, история — 100000 отсчётов на канал.

**Spectrum** — сравнение Raw/Filtered PSD цветами темы с легендой, выделение диапазонов, частота максимального ненулевого filtered-пика, доля raw-мощности в 48–52 Гц. Ось X — Hz, Y — единицы²/Hz или dB. Для log-шкалы нижний предел — −120 dB; данные обработки не меняются.

**Bands** — история Theta, Alpha/Mu и Beta для выбранных каналов и таблица текущих мощностей/асимметрии. `P` переключает режимы. По умолчанию история — 60 секунд, настраивается 1–3600 секунд; общий предел — 10000 точек. `None` не рисуется как ноль; пропуски и пауза разбивают историю на отдельные линии.

**Recording** — редактирование имени, пользователя, электродов, заметки и Destination до начала записи. Во время записи поля заблокированы. Создание каталога проверяется при старте. После остановки показываются длительность, число отсчётов, пропуски, ошибки и путь. При выходе с активной записью требуется `Y`. Заданная CLI `--duration` и headless SIGINT завершают запись автоматически.

После EOF или отключения источник закрывается и запись сбрасывается; TUI остаётся открытым до `q`. Для нового подключения нужно перезапустить приложение.

### 8.3. Особенности обработки

- Каждый канал имеет отдельное состояние фильтра.
- Пропуск сбрасывает непрерывное спектральное окно и фильтры; значения не интерполируются.
- Неконечные значения остаются в RAW, но дают `None` в filtered и флаг `InvalidPacket`.
- PSD — односторонний периодограммный спектр с окном Hann; интеграл PSD даёт мощность в единицах².
- Theta 4–8, Alpha/Mu 8–13, Beta 13–30 Гц — **оценки мощности**, не отдельные сигналы.
- Изменение от baseline: `100 × (power / baseline − 1)`.
- Асимметрия: `(P1 − P2) / (P1 + P2)`; доступна только при подтверждённой общей шкале времени.

## 9. Формат сеанса

**Версия 1** (обычная запись) и **версия 2** (импорт, с необязательным `provenance`).

```text
session-directory/
  metadata.json
  raw.csv
  events.csv
```

### 9.1. `metadata.json`

Версия формата/приложения, Unix-время начала записи в миллисекундах, устройства, каналы, временная шкала, единицы, синтетический seed и **вся эффективная конфигурация**. Идентификаторы устройств уточняются по первому блоку атомарной заменой metadata-файла.

### 9.2. `raw.csv`

Колонки: `block_sequence`, `block_started_ns`, `sample_rate_hz`, `source`, `synchronized_clock`, `block_flags`, общие `sequence`/`timestamp_ns` и для каждого канала `chN_id`, `chN_device`, `chN_sequence`, `chN_timestamp_ns`, `chN_value`, `chN_flags`.

Общие номер/время берутся из первого присутствующего канала; для анализа используйте индивидуальные поля. У несинхронных устройств отсутствующий канал имеет пустые ячейки, **не нули**. Флаги кодируются JSON-массивами внутри CSV-полей. Исходные f64 сохраняются с точностью обратного чтения. Отсутствующие отсчёты не создают искусственных строк.

### 9.3. `events.csv`

Колонки: `timestamp_ns`, `kind`, `text`. Метки, подключения/отключения, ошибки, пропуски, артефакты. События DSP содержат `block=<номер>` для связи с raw. CSV корректно экранирует запятые, кавычки и переносы строк.

### 9.4. Временные метки

Наносекунды относительно начала **источника**, а не начала каждой записи; несколько записей одного запуска продолжают эту шкалу. Wall-clock начала записи хранится отдельно в metadata. Для synthetic номера и время определяет модель.

## 10. Воспроизведение

```sh
lemon replay recordings/ИМЯ-КАТАЛОГА
lemon replay recordings/ИМЯ-КАТАЛОГА --headless --speed 2
```

- Чтение потоковое: вся запись в память не загружается.
- Сохраняются номера, исходные значения и временные метки, включая относительные сдвиги каналов.
- Блок выдаётся по времени последнего отсчёта; скорость меняет только темп выдачи.
- Метки и системные события воспроизводятся с префиксом `Replay/`. Префикс не превращает историческое событие отключения в ошибку текущего устройства.
- Число каналов и частота всегда берутся из metadata.
- Без `--config` обработка восстанавливается из metadata.
- С `--config` используются пользовательские настройки обработки: можно сравнить иной notch/полосу с тем же RAW.
- Фильтры стартуют с нулевого состояния; начальные filtered-значения могут отличаться от первоначального live-сеанса.

## 11. Внешние записи: import, replay, export

Один путь обработки: внешний импорт → native `RawSignalBlock` → существующие Replay/Processor → TUI. Импортёр находится в `storage::external`; отдельного DSP для CSV/DAT нет.

| Вход | Поддержка |
|---|---|
| Каталог LEMON | Существующий `SessionReader`; metadata v1 и v2 |
| `session/raw.csv` | Автоматически открывается родительский native-сеанс при наличии metadata и events |
| Обычный CSV | 1–2 канала, заголовок или без него, comma/semicolon/tab/whitespace, BOM, CRLF/LF |
| DAT BiTronics | Без заголовка, две колонки `time value`, разделённые пробелами/tab |
| Каталог BiTronics | Единственный однозначный набор DAT A0/А0 и A1/А1; размеры каналов могут отличаться |
| DMOV | Прямой ограниченный декодер профиля Лаб2 (`T`, A0/A2); для прежних неподдерживаемых профилей — связанные A0/A1 DAT при однозначном наборе |

```sh
# Replay внешних записей
lemon replay recordings/session-name
lemon replay recordings/session-name/raw.csv
lemon replay signal.csv --speed 2
lemon replay "$HOME/Downloads/Лаб1/Фон"
lemon replay "$HOME/Downloads/Лаб1/Фон/Фон_А0.dat"
lemon replay "$HOME/Downloads/Лаб1/Фон/7_9_2026_10_55_17.dmov"

# Если номинальная частота известна из надёжного источника
lemon replay signal.dat --sample-rate 250 --units 'uV'

# Постоянный сеанс: metadata.json + raw.csv + events.csv
lemon import signal.csv
lemon import signal.dat --sample-rate 250 --output recordings/imported-session
lemon import experiment.dmov --output recordings/imported-experiment

# Произвольная таблица: индексы с нуля или точные имена заголовков
lemon import table.csv --delimiter semicolon --time-column timestamp_ms \
  --channel-column EEG_L --channel-column EEG_R \
  --channel-name left --channel-name right --units 'uV'
lemon import values.csv --sample-rate 250 --channel-column 0

# Безопасный экспорт long-form CSV
lemon export recordings/imported-session --format csv --output experiment.csv
```

`--units` — заявление пользователя, масштаб амплитуд не пересчитывается. Не указывайте физические единицы без подтверждения. DAT A0/A1 — идентификаторы экспортированных каналов; их соответствие физическим электродам/модальностям не доказано.

### 11.1. Поведение `import` и `replay`

`import --output` создаёт **ровно указанный новый каталог**; его родитель должен существовать. Без `--output` создаётся уникальный сеанс в стандартном каталоге записей с обычным приоритетом CLI/env/Settings/config. Существующие результаты не перезаписываются.

`replay` внешнего файла выполняет двухпроходный импорт во временный каталог ОС, который удаляется при штатном завершении, затем использует обычный native-replay. Это занимает время до открытия TUI и временное место на диске, но не создаёт постоянной записи. Исходные файлы открываются только для чтения. После SIGKILL временный каталог может остаться в каталоге ОС.

### 11.2. Определение колонок и ошибки

В заголовке автоматически распознаются `time`, `timestamp`, `timestamp_s` (секунды), `timestamp_ms` и `timestamp_ns`. Имя, указанное через `--time-column`, использует те же правила единиц; произвольное имя и индекс без заголовка трактуются как секунды. Без заголовка 2/3 числовые колонки означают время + один/два канала. Индексы колонок начинаются с **0**.

Без времени нужен `--sample-rate`. Амплитуды — конечные числа с точкой. Времена — неотрицательные десятичные числа с точностью не мельче наносекунды; экспоненциальная запись времени не поддерживается. Целые наносекунды не проходят через f64, поэтому epoch timestamps не теряют младшие разряды.

CSV с повторяющимся/убывающим временем отклоняется; DAT допускает повторы, но отклоняет обратный ход. NaN/Infinity, повреждённые строки и неверное число полей завершают импорт диагностикой пути/строки. Многострочные CSV-поля не поддерживаются для числовых таблиц. Пустая ячейка CSV означает отсутствующий отсчёт; нули и интерполяция не создаются.

**Ограничения:** строка 64 KiB, поле 1024 байта, 32 колонки, максимум 2 выбранных канала, до 32 DAT-кандидатов, 4096 оценок интервала/частоты в памяти, блок записи не более 256 входных строк.

### 11.3. Частота, время и объединение каналов

Явный `--sample-rate` имеет приоритет и помечается `user`. Иначе CSV использует медиану частот `1/dt` первых максимум 4096 положительных интервалов. DAT использует интервалы **между строками через 256 отсчётов**, частоты `256/dt`, максимум 4096 окон; требуется не менее трёх окон. Оценка отклоняется, если `(Q75−Q25)/median > 15%`. Для двух DAT берётся среднее двух медианных оценок, с отказом при отклонении канальной оценки от среднего более 10%. Все такие частоты помечаются **estimated**.

CSV сохраняет исходные интервалы, вычитая общее начало; без времени строится `index / sample_rate`. Для DAT создаётся **собственная** равномерная шкала каждого канала: `first_time − common_origin + index / sample_rate`. Скачок исходного времени более 10 номинальных периодов сохраняется как разрыв. Такая реконструкция меняет длительность относительно пакетных меток и не восстанавливает неизвестные моменты получения каждого отсчёта.

Для временных разрывов CSV >2.5 номинальных периодов и обнаруженных разрывов DAT вставляется один **виртуальный пропуск sequence**, событие `ImportGap` и флаг `LostSample`. Это заставляет DSP сбросить фильтры/FFT-окно; искусственные отсчёты не добавляются. Счётчик потерь в таком случае отражает маркер разрыва, а не доказанное число потерянных аппаратных отсчётов.

Каналы объединяются по времени поступления в общие ограниченные блоки, **не по номеру строки**. Для DAT выставляется `synchronized_clock=false`, поэтому асимметрия отключена даже при совпадающих восстановленных метках.

Параметры DSP не меняются импортёром. Если выбранная/оценённая частота несовместима с существующими фильтрами и диапазонами, укажите совместимый `--config FILE`.

### 11.4. Дубликаты и DMOV

`_1` само по себе не обозначает новый канал. При импорте каталога/DMOV кандидат сравнивается с основным файлом: **размер → потоковый хеш → побайтовая проверка**. Только точная копия исключается и заносится в metadata. Отличающийся `_1`, несколько файлов одного канала или несколько DMOV в каталоге требуют явного выбора DAT; файлы не отбрасываются молча. При передаче отдельного DAT читается только он.

Для прежнего импорта через DAT безопасное правило связи — один DMOV и один однозначный набор A0/A1 в одном каталоге. Прямой декодер Лаб2 вызывается при передаче **самого `.dmov`**, не каталога. Распознанный повреждённый профиль не подменяется DAT.

#### Прямой DMOV Лаб2

```bash
lemon import "$HOME/Downloads/Лаб2/фон/5_10_2026_12_17_26.dmov" \
  --output recordings/lab2-background
# По желанию: --channel-name A0 --channel-name A2
lemon replay "$HOME/Downloads/Лаб2/фон/5_10_2026_12_17_26.dmov" --headless --duration 5
lemon analyze "$HOME/Downloads/Лаб2/фон/5_10_2026_12_17_26.dmov"
lemon report "$HOME/Downloads/Лаб2/фон/5_10_2026_12_17_26.dmov"
```

Проверенный на шести записях формат: `u32 BE` длина тела, байт `T`, `u32 LE` временное поле, затем фрагмент непрерывного потока `A<цифра><u8>`. Масштаб времени **8192 ns/tick** подтверждён сопоставлением с DAT, а не спецификацией аппаратного таймера. Запись ограничена 4096 байтами; поля могут пересекать границы записей. Парсер потоковый, проверяет длину, теги и строго возрастающие пакетные метки. Оборванный/повреждённый файл отклоняется с путём и байтовым смещением до создания сеанса. Wrap/reset времени не поддержан; без checksum/sequence невозможно достоверно обнаружить потерю целой записи.

Извлекаются только **A0 и A2**; остальные теги не становятся ЭЭГ-каналами. В Лаб2 **A0 соответствует `_EMG.dat`, A2 — `_EEG.dat`**: это исторические имена экспорта, не определение модальности. Для проверки DAT используется его числовое представление `f32(u8 / 255 * 5)` и `f32(tick * 8192 / 1e9)` с абсолютным допуском `1e-7`; импортированный Raw остаётся исходными байтами `0…255`, единицы `adc_counts_u8`. DAT пропускает поля, разделённые границей записи, тогда как DMOV-декодер восстанавливает их. Допускаются не более двух начальных строк DAT до первого пакетного времени. Все остальные строки должны совпасть, иначе импорт завершается ошибкой. При отсутствии DAT это явно отмечается как непроверенный по сопутствующему экспорту вход.

Общее время пакета не доказывает синхронность отдельных измерений. Поэтому **`synchronized_clock=false`**, автоматическая асимметрия недоступна. Нативная шкала каждого канала реконструируется по индексу и указанной/оценённой частоте, начинается в первом пакете завершения поля; большие пакетные разрывы (>10 периодов) сохраняются с событием `ImportGap` и сбросом непрерывности DSP. Оригинальные ticks, абсолютное время, смещение файла и соответствие индексам отсчётов каждого пакета сохранены в `DmovPacket` в `events.csv`. Они не выдаются за точные аппаратные метки каждого отсчёта. Пропуски не интерполируются и не заменяются нулями.

Provenance содержит `source_tags`, незаданную `source_channel_map`, `synchronization_status`, `timestamp_source`, `sample_rate_source`, `parser_version`, `validation_against_dat`, `files_used` и предупреждения. **C3/C4 назначает исследователь после проверки подключения**: по спектру, мощности или условию эксперимента соответствие не определяется. До этого используются имена A0/A2. Исходные DMOV/DAT не изменяются.

### 11.5. Metadata и экспорт

Обычная запись совместима с metadata v1. Импорт пишет v2 с необязательным объектом `provenance`: `original_format`, `original_path`, `importer_version`, `detected_channels`, `detected_sample_rate_hz`, `sample_rate_source`, `original_units`, `import_warnings`, `duplicate_files_ignored`, `time_normalization`, `files_used`. Старые v1-сеансы читаются тем же парсером. Предупреждения и использованные файлы также перечисляются в `events.csv` и при запуске CLI.

Экспорт первой версии — **long-form CSV**:

```csv
timestamp,channel,value
0.000000000,A0,1.25
0.004000000,A0,1.5
0.006000000,A1,2.75
```

`timestamp` — секунды с девятью десятичными знаками, индивидуальные наносекунды сохраняются точно; амплитуды сохраняют round-trip-точность f64. Пропущенный отсчёт не создаёт строку. Экспорт сортирует отсчёты внутри одного ограниченного native-блока, не выравнивает каналы и не интерполирует.

## 12. Технический анализ записи

Команда `lemon analyze INPUT` запускает независимый от TUI модуль анализа. Он использует тот же импортёр и тот же `processing::Processor`, что live/replay, поэтому фильтры, FFT, band power и эвристическая оценка качества не имеют отдельной реализации для отчётов.

```bash
lemon analyze recordings/session-name
lemon analyze recording.csv --output reports/music-analysis
lemon analyze recording.dat --sample-rate 250
lemon analyze "$HOME/Downloads/Лаб1/Музыка"
lemon analyze recording.csv --config experiment.json --overwrite
```

Без `--output` создаётся новый каталог `analysis-<session>-N` в каталоге записей. Существующий каталог можно заменить только при явно указанном `--output ... --overwrite`.

### 12.1. `AnalysisBundle`

| Файл | Содержимое |
|---|---|
| `manifest.json` | Версии, эффективная конфигурация, хеш входа, предупреждения |
| `summary.json` | Структурированные численные итоги |
| `summary.md` | Нейтральное техническое резюме |
| `processed.csv` | Потоковый long-form raw/filtered |
| `spectrum.csv` | Каждое окно и PSD bin |
| `band-power.csv` | Мощность каждого диапазона по окнам |
| `quality-events.csv` | Флаги качества и разрывы |

PSD и мощности диапазонов записываются для каждого `hop_samples`-окна; входные блоки перед Processor разбиваются адаптером, поэтому размер блока источника не теряет промежуточные окна. Статистики raw/filtered считаются потоковым алгоритмом Welford; медиана точна до 100 000 окон, после чего записывается `null`. Спектральный пик — максимум усреднённого очищенного PSD по полным непрерывным окнам, без DC, в пределах high-pass…low-pass.

Диапазоны с одинаковыми границами (например, Alpha и Mu 8–13 Гц) сохраняются под обоими именами, но не объявляются независимыми. При пересечении разных границ добавляется предупреждение и победитель не выбирается. Процент изменения около notch рассчитывается в полосе `notch ± 2 Гц` как численное изменение PSD до/после обработки.

Quality — инженерная эвристика. Доли Good/Acceptable/Poor/Disconnected/Unknown считаются по обработанным отсчётам, потери — по разрывам sample sequence. Пропуски остаются отсутствующими значениями и не заменяются нулями. `summary.md` описывает только численные характеристики и выполненную обработку. Модуль `report` читает AnalysisBundle через публичный Interface анализа и не обращается к внутренним структурам DSP.

## 13. Отчёты: local, portable и Colab

`lemon analyze INPUT` создаёт численный AnalysisBundle. `lemon report` представляет его результаты без повторной фильтрации, FFT, band power или оценки качества.

### 13.1. Первый локальный отчёт

Один раз явно настройте окружение:

```bash
lemon report setup
lemon report doctor
# Пересоздать только принадлежащий LEMON venv:
lemon report setup --recreate
```

Требуется Python >= 3.10. Управляемое окружение:

| ОС | Путь |
|---|---|
| macOS | `~/Library/Application Support/LEMON/report-python/` |
| Linux | `~/.local/share/lemon/report-python/` (учитывает `XDG_DATA_HOME`) |
| Windows | `%LOCALAPPDATA%\LEMON\report-python\` |

`setup` создаёт venv, устанавливает зависимости из `report-requirements.txt`, регистрирует пользовательский Jupyter kernel `LEMON Reports`, проверяет импорты и выполняет минимальный notebook. `doctor` ничего не устанавливает и печатает найденный системный Python, путь venv, версии зависимостей, регистрацию kernel, результат тестового notebook и команду исправления. Окружение не создаётся внутри проекта.

После успешного `setup`:

```bash
lemon report "$HOME/Downloads/Лаб1/Музыка"
# Report completed: .../report-Музыка/report.ipynb
```

Notebook не открывается автоматически; для явного открытия — `--open`.
Локальные notebook указывают kernel `LEMON Reports`, поэтому после `setup` VS Code и Jupyter не должны выбирать одноимённый системный Python без зависимостей. Colab notebook сохраняет универсальный kernel `Python 3`.

### 13.2. Режимы и параметры

```bash
lemon report recording.dat --sample-rate 250
lemon report recording.csv --open
lemon report recording.csv --no-execute
lemon report recording.csv --python /path/to/venv/bin/python
lemon report --analysis reports/music-analysis --output reports/music
lemon report recording.csv --portable
lemon report recording.csv --portable --no-execute
lemon report recording.csv --colab
lemon report recording.csv --colab --include-raw
lemon report recording.csv --colab --maximum-embedded-report-mb 25
```

- При первом интерактивном запуске LEMON предлагает `setup`. После отказа создаётся notebook без outputs.
- Неинтерактивный запуск не задаёт вопрос и ничего не устанавливает: при отсутствии окружения сохраняет сгенерированный notebook и возвращает ошибку с инструкцией `lemon report setup`.
- `--python` имеет приоритет, проверяется, но никогда не изменяется.
- `--no-execute` и `--colab` не запускают локальный Python; статус — `not_executed`.
- Обычный запуск выполняет notebook через `nbclient`, но не открывает GUI.
- `--open` требует явного флага и несовместим с ZIP/Colab.
- `--execute` и `--no-execute` конфликтуют.
- `--include-raw` требует `--portable` или `--colab`.
- Positional `INPUT` конфликтует с `--analysis`.

`report-manifest.json` фиксирует режим, версии LEMON/Python/зависимостей, статус выполнения, SHA-256 AnalysisBundle и notebook, наличие полного Raw, параметры встроенного Report Dataset, размеры payload и имя внешнего архива при его наличии.

### 13.3. Локальный каталог

Содержит `report.ipynb`, `report-manifest.json`, `report-requirements.txt`, `report-data.json`, полный `analysis/` и `figures/`. Даже при `--analysis` пакет копируется, поэтому весь каталог можно перемещать. Вход остаётся неизменным. `--output` задаёт каталог; без него имя `report-<input>` в текущем каталоге. Без `--overwrite` результаты не заменяются.

### 13.4. Portable ZIP

`--portable` дополнительно создаёт соседний `report-name.lemon-report.zip`. Внутри: notebook, AnalysisBundle, доступные PNG, требования, README и `SHA256SUMS.json` с хешами файлов. ZIP записывается потоково с Deflate-сжатием и публикуется атомарной заменой. Исходные DAT/DMOV не копируются. Полные Raw/Filtered находятся в `analysis/processed.csv`.

Перенесите один файл `*.lemon-report.zip`, распакуйте его в новый каталог и откройте `report.ipynb`. Встроенный `README.md` содержит команды создания собственного venv. `SHA256SUMS.json` позволяет проверить каждый файл. `--overwrite` заменяет только распознанный отчёт и архив; публикация выполняется через staging.

### 13.5. Google Colab

`--colab` создаёт `report-colab.ipynb` в выходном каталоге. Файл можно загрузить в Colab и выполнить Run all. Он содержит **Report Dataset**: manifest, summary, усреднённые готовые PSD, min/max Raw/Filtered, истории диапазонов и временные bins событий. Это данные для отображения, не новая научная обработка и не полная запись. Сравнение Raw/Filtered показывает envelope всей записи.

Встроенный ZIP кодируется base64 и проверяется SHA-256. Лимит по умолчанию 25 MiB отдельно для base64 payload и распакованных данных. При превышении число визуальных bins снижается с 1200 до 32; extrema сохраняются. Если этого недостаточно, появляется `colab-data.zip` и условная ячейка загрузки через Colab. Запрещены неожиданные имена, `..`, абсолютные пути, symlink, дубликаты, лишние файлы и превышение распакованного размера.

`--include-raw` требует `--colab` или `--portable`. Для Colab заранее выводится размер полного `processed.csv`. Если он не помещается, полный файл сохраняется в `full-raw.zip`, Report Dataset остаётся встроенным, когда позволяет лимит. Colab не выполняет pip install по умолчанию; отдельная ячейка установки выключена (`INSTALL_MISSING_REPORT_PACKAGES = False`) и требует явного изменения пользователем.

## 14. Последовательный порт

### 14.1. Подключение

Закройте Arduino Serial Monitor и другие программы, использующие порт.
`lemon ports` показывает имя и тип порта, а при доступности — USB VID/PID,
серийный номер, производителя и название устройства.

```sh
lemon ports
# CSV: одна строка = один кадр, один или два конечных числа
lemon live --port /dev/cu.usbmodem1101 --baud 115200 --protocol csv --sample-rate 250 --channels 2

# Простой шестибайтовый профиль A0,A1 без счётчика
lemon live --port /dev/cu.usbmodem1101 --baud 115200 --protocol tagged-u8 --sample-rate 333.333 --channels 2 --record
# Или конфигурация (замените имя порта)
lemon live --config examples/serial-tagged-u8.json

# Полный кадр A0..A7,A9, но единственный подключённый сигнал — A0
lemon live --config examples/serial-tagged-u8-a0.json --port /dev/cu.usbmodem1401 --headless --duration 15 --record
# TUI с тем же профилем
lemon live --config examples/serial-tagged-u8-a0.json --port /dev/cu.usbmodem1401 --record
```

Разделение: **Serial transport → SerialDecoder → RawSignalBlock → DSP/TUI/storage**.
Транспорт открывает 8N1 без flow control и читает произвольные фрагменты байтов;
декодер не открывает порт. Нет привязки к производителю аналоговой платы.

- `csv`: `123.5\n` или `123.5,-42\r\n`; LF/CRLF, до 256 байт на строку.
  Некорректные числа, NaN/inf и лишние поля отклоняются; следующая строка
  обрабатывается независимо.
- `tagged-u8`: последовательность двухбайтовых тегов с одним бинарным значением
  после каждого. `serial_frame_tags` задаёт **полный транспортный кадр** (1–32
  уникальных ASCII-тега), `serial_channel_tags` выбирает 1–2 сигнала для LEMON,
  `serial_sequence_tag` — необязательный счётчик modulo 256, не сигнальный канал.
  Остальные поля проверяются для сохранения границ, но не передаются в DSP.
  Все выбранные теги должны присутствовать в кадре, их число равно `channels`.
  По умолчанию сохранён профиль `A0 ? A1 ?`, два сигнала, без счётчика.
  Перевода строки нет; значения могут совпадать с байтами маркеров. При повреждении
  поиск сдвигается к следующему полному кандидату; проверяется весь порядок тегов.
  Без checksum ложная синхронизация теоретически возможна.
- `source.mode = "serial"`, `source.serial_protocol = "csv" | "tagged-u8"`.
  Старый `serial-test` остаётся совместимым псевдонимом, без нового поля выбирается CSV.
  Старые записанные сеансы и их временные метки не меняются.
- Два отдельных порта поддерживаются для CSV (по каналу); tagged-u8 требует один порт.
- `source.block_size` задаёт размер блока (по умолчанию 25 кадров).
  Уже декодированный неполный блок сохраняется при штатной остановке и отключении.
  Незавершённый кадр не превращается в отсчёт.
- Ошибки декодирования агрегируются не чаще раза в секунду, с итоговым событием при завершении.
  Флаг InvalidPacket ставится следующему восстановленному отсчёту.

В `examples/serial-tagged-u8-a0.json` кадр имеет 27 байт:
`A0 ? A1 ? A2 ? A3 ? A4 ? A5 ? A6 ? A7 ? A9 ?`. A8 не ожидается.
Только A0 выбран сигналом; A9 — счётчик, A1…A7 не объявляются ЭЭГ-каналами.
Для двух подключённых сигналов измените `channels` на `2` и
`serial_channel_tags` на `["A0", "A1"]`; `serial_frame_tags` остаётся прежним.
Порт передаётся через CLI; профиль намеренно содержит пустой `ports` и сам по себе
без `--port` не является готовой конфигурацией подключения.

### 14.2. Время, единицы и ограничения

Новая Serial-запись использует реконструированные host-side timestamps:
`round((frame_index + inferred_missing_frames) × 1e9 / nominal_sample_rate)`.
USB-время чтения не является временем отдельного отсчёта. В Raw sequence —
развёрнутый индекс от нуля; скачки аппаратного счётчика создают пропуски этого индекса
и временной оси, но не искусственные отсчёты. CSV сохраняет номера строк, включая отклонённые.
`synchronized_clock = false`, частота номинальная, не измеренная устройством.
Для tagged-u8 без конфигурации нужно явно передать `--sample-rate`.

В metadata сохраняются протокол, номинальная частота, единицы и принцип времени;
событие SerialTiming описывает ограничения. При настроенном счётчике приращение
`(next − previous) mod 256` равно 1 в норме (включая 255→0). При приращении d>1
помечаются минимум d−1 отсутствующих кадров: флаг и событие LostSample с числом.
Повтор счётчика помечается InvalidPacket/SequenceDiscontinuity, без выдуманных 255 потерь.
Сброс, перестановку и потери кратно 256 нельзя однозначно различить; оценка потерь
модульная. Без `serial_sequence_tag` потеря целого кадра не обнаруживается.
Аппаратной временной метки и checksum нет. Скорость probe — диагностическая
оценка и не заменяет автоматически номинальные 333.333333 Гц профиля.
A0 и A1 измеряются последовательно, точный сдвиг неизвестен; компенсация не выполняется.
Два порта не получают общие аппаратные часы от совпадения номинальных меток.

После `map(analogRead(pin), 0, 1023, 0, 255)` остаётся 8-битное значение
`0…255`; единицы по умолчанию `adc_counts_u8`. Это не вольты и не микровольты.
`--units TEXT` меняет только подпись, не масштаб. Параметры DSP автоматически
не перенастраиваются: пороги качества требуют проверки под выбранные единицы.

UNO может перезапуститься при открытии порта. `--startup-delay-ms 2000`
(`source.serial_startup_delay_ms`) даёт дополнительное начальное время до
декодирования: стартовые байты читаются и исключаются до проверки счётчика,
чтобы кадры до reset не создавали ложных потерь после reset. Их объём фиксируется
событием SerialStartup. В live `--duration` не включает этот заданный период:
при задержке 2 с и длительности 15 с команда работает около 17 с.
Обычный `source.serial_idle_timeout_ms` — 3000 мс без корректных кадров.
Сообщения различают отсутствие байтов и отсутствие распознаваемых кадров.

### 14.3. Диагностика неизвестного потока

```sh
lemon probe --port /dev/cu.usbmodem1101 --baud 115200 --duration 10 --output capture.bin
lemon probe --help
```

Probe ничего не отправляет, не включает TUI/DSP. Сначала читает и отделяет
байты reset grace period, затем сохраняет точные байты отдельного измерительного
интервала `--duration`. Скорость считается только за измерение, не за стартовую задержку.
Выводит оба времени, объём отброшенных стартовых байтов, объём дампа, первые 128 байт
как ASCII/hex, LF, полный кандидат кадра, длину, число кадров, префикс/суффикс и мусор
между кадрами. Ищет циклы `A<цифра> + байт` по первым 64 KiB, затем проверяет весь дамп
потоково; поля с не менее 95% нормальных приращений предлагает как кандидаты счётчика
(с числом нарушений). Рампа сигнала тоже может выглядеть как счётчик: это эвристика.
Сигнальные теги всегда выбирает пользователь; пример конфигурации содержит явные
заполнители для сигналов и номинальной частоты. A9 не выбирается сигналом автоматически.

По умолчанию команда длится около 2 + 10 секунд (reset grace, затем измерение;
погрешность границы ограничена одним чтением с timeout до 10 мс),
максимум 64 MiB (`--max-bytes`, предел 1 GiB), буфер чтения 4096 байт.
Ctrl+C сохраняет уже принятый дамп. Существующий файл требует `--overwrite`.
При ошибке чтения неполный дамп остаётся на диске и явно обозначается в ошибке.
Автоматические тесты используют синтетические кадры и виртуальные порты;
аппаратная проверка относится только к фактически подключённому устройству.

Не требуется менять TUI или Processor. Подписку добавляют при сборке приложения:

```rust
use core::{Broadcast, Config, ProcessedSignalBlock};
use app::Runtime;

let config = Config::default();
let source = source::open(&config.source)?;
let mut bus = Broadcast::<ProcessedSignalBlock>::default();
let features = bus.subscribe(64);
let runtime = Runtime::start_with_bus(config, source, false, bus)?;
// Собственный поток: features.receiver.recv() -> Arc<ProcessedSignalBlock>.
// Проверяйте features.dropped; это ограниченный, а не гарантированно lossless канал.
// После работы: runtime.shutdown()?; дождаться завершения своего потребителя.
```

Встроенный тестовый потребитель получает блоки независимо от TUI; счётчики видны в Sources и итоговом выводе. Для lossless-потребителя потребуется явно выбрать политику backpressure; raw уже записывается напрямую.

## 16. Проверки и ограничения

### 16.1. Команды проверки

```sh
cargo fmt --all --check
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo build --locked
python3 scripts/smoke.py
python3 scripts/report_smoke.py
python3 scripts/test_report_unpack.py
python3 scripts/test_report_presentation.py
```

### 16.2. Что покрыто тестами

Rust-тесты проверяют парсер, каналы, пропуски, сохранение состояния фильтров, PSD известной синусоиды, относительную мощность/baseline, notch, короткое окно, Найквист, seed, кольцевые буферы, round-trip записи, маркеры replay, повреждённый CSV, независимость записи от TUI, стороннего подписчика и завершение после отключения. На Unix тесты `TTYPort::pair()` проверяют serial transport, восстановление после ошибочных/слишком длинных строк, два порта и отключение.

`smoke.py` запускает настоящий TUI в PTY, переключает экраны, включает запись, вводит метку, ставит визуализацию на паузу, выходит через `q` и `Ctrl+C`, проверяет восстановление termios/курсора/alternate screen и воспроизводит запись с точным совпадением количества отсчётов. Проверяется также внешний SIGINT в headless. На macOS открытие обычного PTY как serial с аппаратной baud-настройкой не поддерживается драйвером: эта часть CLI smoke пропускается; транспорт проверяется Rust-тестами пары PTY. На Linux smoke дополнительно проверяет serial CLI.

`report_smoke.py` всегда проверяет генерацию, а при наличии зависимостей — nbformat validation, выполнение всех ячеек, шесть PNG и неизменность входа. Иначе execution smoke явно пишет SKIP. Smoke-тесты ничего не устанавливают; установка выполняется только явной командой `lemon report setup` либо после интерактивного подтверждения.

### 16.3. Ограничения

- Один источник на запуск; до двух каналов.
- Нет автоматического reconnect, восстановления повреждённого CSV и гарантированного real-time планировщика.
- Один Hann-периодограммный спектр вместо усреднения Welch.
- Baseline задаётся конфигурацией.
- Очищенные отсчёты не записываются отдельным файлом.
- Пороговые эвристики не заменяют анализ артефактов ЭЭГ.
- История Waveform — 10 секунд и 100000 точек на канал; история Bands — 10000 точек; список событий — 30 строк.
- Размер FFT — 65536, блока — 4096, CSV-записи — 64 КиБ, metadata/config/settings — 1 МиБ.
- Нет облака, БД, сетевого API и фонового бесконечного накопления данных.
- `report setup` — единственная штатная команда LEMON, которая устанавливает Python-пакеты; ей требуется сеть или настроенное зеркало. Обычный `report` не изменяет окружение.
- Report Dataset в Colab содержит визуализационные агрегаты. Полные отсчёты доступны только при явно указанном `--include-raw` или внутри полного portable ZIP.
- Min/max envelope сохраняет экстремумы, но не точное положение пика и нескольких разрывов внутри одного временного bin.
- Внешний Colab data archive требуется загружать вручную, если Report Dataset не помещается в установленный лимит.
- RAII и panic hook восстанавливают терминал при штатном выходе и Rust panic; SIGKILL, отключение питания и аппаратный сбой ОС программно обработать невозможно. При принудительном уничтожении процесса часть последней секунды буферизованной записи может не сохраниться.

### 16.4. Уточнения анализа и воспроизводимости

- Адаптер анализа подаёт по одному отсчёту в отдельный существующий Processor каждого канала; так не теряются окна при разной длине каналов.
- Состояния фильтров сбрасываются на разрывах последовательности, времени (более 1.5 периода) и смене источника. Формулы фильтров и PSD не изменены. Индекс окна локален для канала.
- Quality в анализе считается на одноотсчётных блоках; поэтому доли могут отличаться от live с крупными блоками. Все полные численно допустимые окна включаются в статистики, в том числе помеченные артефактами: проверяйте `quality-events.csv`. Асимметрия в анализе не рассчитывается.
- Стандартное отклонение — Welford с делителем n−1.
- Мощность около notch — сумма PSD bins в `notch ± 2 Hz`, умноженная на Δf; процент уменьшения = `100×(1−after/before)`, только при включённом notch и ненулевой исходной мощности.
- Summary сохраняет исходные ID каналов. В manifest записываются хеши использованных файлов; внутренние хеши предназначены для идентификации в этой версии, не для криптографической проверки.
- Старые отчёты, созданные до исправления адаптера, следует пересоздать.
- Границы спектральных окон в AnalysisBundle берутся из временных меток первого и последнего отсчётов окна, а не восстанавливаются по номинальной частоте. Распределение качества содержит все пять категорий, включая нулевые количества.
- Report Dataset сохраняет для сгруппированных событий количество и первый/последний timestamps, а не только наличие маркера.
- Portable ZIP создаётся потоково с Deflate-сжатием. Проверка распаковки — `python3 scripts/test_report_unpack.py`.
- Генерация отчёта выполняется в staging-каталоге: ошибка до публикации не удаляет прежний отчёт.
